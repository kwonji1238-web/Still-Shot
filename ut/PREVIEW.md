# 배포하기 전에 직접 확인하는 방법

참가자에게 주소를 보내기 전에, 디자이너가 혼자 화면과 기록을 확인하는 순서예요.
명령어는 **한 줄씩 그대로 복사해서** 넣으면 돼요.

## 먼저 알아 둘 것: 주소 뒤에 붙이는 글자

| 붙이는 글자 | 하는 일 |
| --- | --- |
| `?ut=1` | UT 모드를 켜요. 이게 없으면 기존 서비스 그대로예요 |
| `&p=TEST01` | 참가자 번호. **TEST로 시작하면 연습용**이라 시트에 `is_test` 표시가 붙어요 |
| `&m=inperson` / `&m=remote` | 직접 만남 / 원격 |
| `&dry=1` | **시트로 보내지 않고** 화면의 "기록" 패널로만 확인해요 |
| `&debug=1` | 시트로 **보내면서** "기록" 패널도 보여 줘요 |
| `&fast=1` | **TEST로 시작하는 번호에서만** 제한 시간이 짧아져요(과업 1은 10초, 과업 2는 8초). 다른 번호에서는 무시돼요 |

> **참가자에게 보내는 주소에는 `dry`, `debug`, `fast`를 붙이지 마세요.** `dry=1`이 붙어 있으면 참가자의 기록이 시트에 **하나도 안 들어가요.**
> 참가자 주소는 `https://배포주소/?ut=1&p=P01&m=remote` 모양이에요.

"기록" 패널은 화면 맨 위 UT 바의 **기록 N** 버튼을 눌러야 열려요(기본은 접혀 있어요). 지도·바텀시트를 가리지 않아요.
`dry=1`, `debug=1`이 둘 다 없으면 이 버튼과 패널은 아예 만들어지지 않아요.

## a) 내 컴퓨터에서 열기

### a-1. 시트 연결 없이 화면만 확인하기

1. VS Code에서 이 프로젝트 폴더를 열어요.
2. 위쪽 메뉴에서 **터미널 → 새 터미널**을 눌러요. 화면 아래쪽에 글자를 입력하는 창이 열려요. (단축키: `Ctrl` + `` ` ``)
3. 그 창에 아래 한 줄을 입력하고 `Enter`를 눌러요.
   ```
   npm run dev
   ```
4. `http://localhost:8000  ...` 라는 글이 나오면 서버가 켜진 거예요. 브라우저가 저절로 열릴 수 있어요. 열린 화면은 UT 모드가 아니니 그냥 닫아도 돼요.
5. 브라우저(크롬 또는 엣지) 주소창에 아래를 붙여 넣고 `Enter`를 눌러요.
   ```
   http://localhost:8000/?ut=1&p=TEST01&m=inperson&dry=1
   ```
6. 모바일 폭으로 보려면 `F12`를 눌러 개발자 도구를 열고, `Ctrl` + `Shift` + `M`(기기 툴바)을 눌러 폭을 `390`으로 맞춰요. 새로고침(`F5`)을 한 번 해요.
7. 화면 위 UT 바의 **기록 N**을 눌러 패널을 열어요. 이 모드에서는 시트로 아무것도 안 가요.

주소는 꼭 **`localhost:8000`** 으로 열어요. 카카오 지도는 이 주소가 등록돼 있어서 이 주소에서만 지도가 떠요. (`127.0.0.1`로 열면 지도가 안 뜰 수 있어요. 확인 못함.)

### a-2. 시트 주소·토큰까지 넣고 확인하기

시트 만들기(`ut/SETUP.md` 1~4번)를 먼저 끝내세요. 값은 **여기에 적지 말고** 아래 위치에만 넣어요.

1. 프로젝트 폴더의 **`.env`** 파일을 열어요.
2. 맨 아래에 두 줄을 추가해요. `=` 뒤에 값을 붙여 넣어요(따옴표·공백 없이).
   ```
   UT_ENDPOINT=
   UT_TOKEN=
   ```
3. 저장해요.
4. 서버가 켜져 있으면 터미널 창을 눌러 `Ctrl` + `C`로 끄고, 다시 `npm run dev`를 입력해요.
5. 터미널에 `UT 설정 (UT_ENDPOINT 있음, UT_TOKEN 있음)`이 나오는지 봐요. `없음`이면 `.env`를 다시 확인하세요.
6. 브라우저에서 아래로 열어요. (`debug=1`: 시트로 보내면서 패널도 보여 줘요.)
   ```
   http://localhost:8000/?ut=1&p=TEST01&m=inperson&debug=1
   ```
7. 한 번 진행한 뒤 구글 시트의 `responses` 탭에 줄이 늘었는지 봐요.

### a-3. 서버 끄기

터미널 창을 한 번 눌러 선택한 뒤 **`Ctrl` + `C`** 를 눌러요. (끝낼지 묻는 글이 나오면 `Y` 입력 후 `Enter`.) 터미널 창을 닫아도 꺼져요.
`questions.json`(질문·문구·제한 시간)을 고쳤으면 서버를 끄고 `npm run dev`를 다시 입력해야 반영돼요.

## b) 내 휴대폰에서 열기 (같은 와이파이)

1. 컴퓨터와 휴대폰이 **같은 와이파이**에 연결돼 있어야 해요. (회사·카페 와이파이는 기기끼리 연결을 막아 놓은 곳이 있어요. 확인 못함.)
2. 컴퓨터에서 `npm run dev`로 서버를 켜 둬요(a-1).
3. 컴퓨터 주소 찾기: 터미널 창에 아래를 입력해요.
   ```
   ipconfig
   ```
   나온 글에서 **`IPv4 주소`** 옆의 `192.168.0.12` 같은 숫자를 찾아요. (와이파이 항목 안에 있는 것을 보세요.)
4. 휴대폰 브라우저 주소창에 아래 모양으로 입력해요. 숫자 부분을 3번에서 찾은 값으로 바꿔요.
   ```
   http://192.168.0.12:8000/?ut=1&p=TEST01&m=inperson&dry=1
   ```
5. 안 열리면: 컴퓨터에서 처음 서버를 켤 때 **Windows 방화벽 허용 창**이 뜰 수 있어요. 허용해 주세요(확인 못함: 창 문구). 이미 거부했다면 서버를 껐다 켜거나 방화벽 설정에서 Node.js를 허용해야 해요.

**카카오 지도가 안 뜰 수 있어요.**
- 이유(추정, 확인 못함): 카카오 지도는 등록한 주소에서만 뜨는데, 등록된 주소는 `http://localhost:8000`이에요. 휴대폰에서 연 `192.168...` 주소는 등록되어 있지 않아 지도가 막힐 가능성이 커요.
- 지도가 안 뜨면 서비스는 지도 없이 **목록·상세·코스**로 동작하게 만들어 놨어요. UT 질문과 기록 확인은 그대로 할 수 있어요.
- 휴대폰에서 **지도까지** 확인하려면 두 가지 중 하나를 써요.
  1. (권장) 브랜치 배포 주소를 카카오 개발자 사이트의 JavaScript SDK 도메인에 등록하고, 그 주소를 휴대폰에서 열어요(c번).
  2. `http://192.168...:8000`을 도메인에 등록해 보기. 카카오가 IP 주소 등록을 받아 주는지, 주소가 바뀔 때마다 다시 등록해야 하는지는 확인 못함이에요.
- 이 주소는 `http://`(보안 연결이 아님)이라, 휴대폰에서 기록 패널의 **[결과 복사]** 가 막힐 수 있어요. 코드에 대체 방법을 넣어 두었지만 휴대폰에서 되는지는 확인 못함이니, 실제로 눌러 보세요.

## c) 브랜치 배포 후, 참가자에게 주소를 보내기 전에 나만 먼저 확인하는 순서

(푸시와 배포는 제가 대신 하지 않아요. 디자이너가 "푸시해도 돼"라고 알려 주신 뒤에 진행해요.)

1. **배포 주소 알아내기**: Netlify에서 `ut-mode` 브랜치 배포의 주소를 찾아요. 보통 `https://ut-mode--사이트이름.netlify.app` 모양이에요(확인 못함: 브랜치 배포가 켜져 있는지, 정확한 주소 모양).
2. **환경변수 확인**: `ut/SETUP.md`의 5-3번대로 빌드 로그에 `UT_ENDPOINT 있음, UT_TOKEN 있음`이 나오는지 봐요.
3. **카카오 도메인 등록**: 카카오 개발자 사이트의 JavaScript SDK 도메인에 1번의 주소를 등록해요(사람이 해야 하는 일).
4. **내 휴대폰에서 연습으로 열기**: 아래 주소를 열어요(주소 앞부분은 1번의 주소).
   ```
   https://배포주소/?ut=1&p=TEST01&m=remote&debug=1
   ```
5. **리허설 6개 해 보기**: 아래 "리허설 시나리오"를 위에서부터 하나씩 해요. 패널에 나와야 할 기록이 맞는지 봐요.
6. **시트 확인**: 구글 시트의 `responses` 탭에 연습 줄이 들어왔는지 봐요. `is_test` 열이 TRUE인지, `participant_id`가 TEST01인지 확인해요.
7. **참가자 주소 만들기**: `dry`, `debug`, `fast`를 **뺀** 주소를 만들어요.
   ```
   https://배포주소/?ut=1&p=P01&m=remote
   ```
8. **그 주소를 한 번 더 열어 보기**: 패널 버튼(기록)이 **안 보이는지** 확인해요. 보이면 `debug`나 `dry`가 남아 있는 거예요. 이 확인은 번호를 `TEST99`처럼 연습용으로 바꿔서 해요(진짜 P01 기록이 시트에 섞이지 않게).
9. **연습 기록 정리**: 시트에서 `is_test`가 TRUE인 줄은 필터로 거르거나 지워요.
10. 그다음 **체크리스트**(맨 아래)를 끝까지 확인하고 참가자에게 보내요.

## d) 기존 서비스가 `?ut=1` 없이 똑같이 동작하는지 확인하기

"원래 서비스"(main 배포 주소)와 "UT 브랜치 배포 주소"를 `?ut=1` **없이** 나란히 열어 비교해요.

1. 브라우저 창 두 개를 열어요. 창을 선택하고 `윈도우 키` + `←` / `→`로 화면 반반에 나눠요.
2. 왼쪽 창: 지금 운영 중인 서비스 주소(예: `https://운영주소/`). 오른쪽 창: UT 브랜치 배포 주소를 **`?ut=1` 없이** 연 것(예: `https://ut-mode--사이트이름.netlify.app/`).
   - 내 컴퓨터에서 확인할 때는 오른쪽 창을 `http://localhost:8000/`로 열어요.
3. 두 창의 폭을 같게 하고, 아래를 **똑같이 조작**하면서 서로 같은지 봐요.
   - 홈 모양, 글자, 색, 라이트·다크 전환
   - "요즘 뜨는 촬영지" 두 줄
   - 작품 검색 → 지도 핀과 바텀시트 → 촬영지 상세 → "근처에 이런 곳" → "이 근처 코스 보기"
   - 뒤로 가기, 주소 복사
4. 같은지 한 번 더 확인하려면 오른쪽 창에서 `F12` → **네트워크** 탭을 열고 `F5`로 새로고침한 뒤, 검색칸에 `ut/`를 입력해요. **한 줄도 안 나오면** UT 파일이 하나도 안 불러와진 거예요.
5. 오른쪽 창 화면 위에 **UT 바**가 보이면 안 돼요. 보이면 주소에 `?ut=1`이 남아 있는 거예요.

## 리허설 시나리오

아래 시나리오는 모두 `…/?ut=1&p=TEST01&m=inperson&dry=1`(시트로 안 보냄)로 시작해요. ⑥만 `debug=1`과 시트 연결이 필요해요.
패널은 UT 바의 **기록 N** 버튼으로 열어요. 한 줄은 `이벤트 이름 · 값 · 과업 경과 시간`으로 보이고, 그 아래 작은 글씨가 `extra_json`이에요.
다시 시작하려면 개발자 도구(`F12`) → **애플리케이션** 탭 → 저장소 → 로컬 저장소에서 `ut-`로 시작하는 항목을 지우고 새로고침하세요(확인 못함: 탭 이름은 브라우저마다 달라요). 참가자 번호를 `TEST02`처럼 바꿔 열어도 새로 시작돼요.

| 시나리오 | 하는 방법 | 패널에 나와야 할 기록 |
| --- | --- | --- |
| ① 정상 경로 (모바일 폭 390) | 폭 390으로 열기 → [동의하고 시작] → Q1·Q2 답하기 → [시작] → 홈의 "요즘 뜨는 촬영지" 중 작품 선택 → 목록의 촬영지 **줄을 한 번 눌러** 보기 → 줄 **오른쪽 화살표(>)** 누르기 → S1 점수 → 상세에서 "근처에 이런 곳" 카드 1곳 누르고 뒤로 가기 → UT 바 **펼치기** → [정했어요] → S2 점수(S1과 다른 점수) → S2-1 → "이 근처 코스 보기" → **펼치기** → [다 봤어요] → S3·Q3·Q4·E1·E2·Q5·F2 → 종료 화면 | `ut_start` → `consent` → `q_answer Q1`, `q_answer Q2` → `task_start`(값 90) → `screen_view`(work) → `spot_select` → `spot_tap`(`{"kind":"arrow"}`) → `pause`(`{"reason":"modal"}`) → `q_answer S1`(`{"s1_after_detail":false,...}`) → `resume`(modal) → `screen_view`(spot) → `task_end`(success) → `task_start`(값 60) → `nearby_card_tap` → `task_end`(decided, `{"success":true,"nearby_taps":1,...}`) → `q_answer S2` → `q_answer S2-1` → `course_button_tap`(`{"course_found_unprompted":false,...}`) → `screen_view`(course) → `course_view` → `q_answer S3`, `Q3`, `Q3_reason`, `Q4`, `E1`, `E2`, `Q5`, `F2` → `ut_end` |
| ② 과업 1 시간초과 | 주소를 `…/?ut=1&p=TEST01&m=inperson&dry=1&fast=1`로 열기 → 동의 → Q1·Q2 → [시작] → **아무것도 하지 않고 10초 기다리기** → 안내 문구 확인 | `task_start`(값 10) → `task_end`(값 `timeout`, `{"success":false}`, 경과 약 10.0초). UT 바에 "이어서 아무 촬영지의 상세 화면을 열어 주세요." 안내가 떠요. 이어서 상세로 가면 `q_answer S1`(`{"s1_after_detail":false,"task1_failed":true}`)이 기록돼요 |
| ③ 코스 화면만 열고 [정했어요] 누르기 (성공으로 기록되는지) | ①처럼 S1까지 진행해 상세에 도착 → "근처에 이런 곳" 카드는 **누르지 말고** "이 근처 코스 보기"를 눌러 코스 화면 열기 → UT 바 **펼치기** → [정했어요] | `task_start`(task2) → `course_button_tap`(`{"course_found_unprompted":true,...}`) → `screen_view`(course) → `course_view`(`{"during_task2":true,...}`) → `task_end`(값 `decided`, `{"success":true,"nearby_taps":0,"course_opened_before_s2":true,...}`) |
| ④ 결과 없음 검색어 | 홈 화면의 검색창에 `zzzzqq`를 입력하고 `Enter` (과업 1 중이든 아니든 상관없어요) | `search_submit`(값 `zzzzqq`) → 입력 후 약 1초 뒤 `search_no_result`(값 `zzzzqq`). 같은 검색어는 `search_no_result`가 한 번만 나와요 |
| ⑤ 새로고침 후 이어짐 | 과업 2 중에 `F5`로 새로고침 → UT 바와 남은 시간 확인 → 질문 창 중간에 새로고침도 해 보기 | 과업 중이면 `resume`(`{"reason":"reload"}`)과 `screen_view`가 새로 나오고, UT 바의 남은 시간은 새로고침하기 전 값에서 이어져요. 단계는 그대로(예: 과업 2)고 `ut_start`, `consent`는 다시 나오지 않아요. 질문 창에서 새로고침하면 이미 답한 문항은 답이 채워진 채로 나와요 |
| ⑥ 인터넷을 끊었다 켜도 기록이 남는지 (시트 연결 필요) | `…&debug=1`로 열기 → `F12` → **네트워크** 탭 → 속도 제한 목록에서 **오프라인** 선택 → 화면 몇 번 이동하기 → 패널의 "전송 대기" 건수 확인 → 다시 **제한 없음**으로 되돌리기 → 몇 초 기다리기 (오프라인인 동안은 새로고침하지 마세요. 페이지 자체가 안 열려요) | 오프라인 동안 "전송 대기 N건"이 늘어나요 → 온라인으로 돌아온 뒤 "전송 대기 0건"으로 줄고, 시트에 그 줄들이 들어와요. 새로고침으로 같은 기록이 한 번 더 가더라도 시트는 `event_id`로 걸러 **중복해서 적지 않아요** |

## 참가자에게 주소를 보내기 전 체크리스트

- [ ] **1. 시트에 행이 들어온다** — `…&debug=1`로 TEST 번호를 끝까지 진행한 뒤 구글 시트 `responses` 탭의 줄 수가 늘었는지, 마지막 줄이 `ut_end`인지 본다.
- [ ] **2. 시트 설정이 배포본에 들어갔다** — Netlify 빌드 로그에 `UT_ENDPOINT 있음, UT_TOKEN 있음`이 나오고 `https://배포주소/ut/config.js`의 따옴표 안이 비어 있지 않은지 본다.
- [ ] **3. 리허설 6개가 통과한다** — 위 표의 ①~⑥을 하고 패널(또는 시트)의 기록이 표와 같은지 본다.
- [ ] **4. 휴대폰 실기기에서 글자 크기가 괜찮다** — 휴대폰 설정에서 글자를 "크게"로 바꾼 상태로 질문 창을 열어 글자가 잘리거나 버튼이 화면 밖으로 나가지 않는지 본다.
- [ ] **5. 휴대폰 키보드가 입력칸을 가리지 않는다** — E2·F2의 입력칸을 눌러 키보드가 올라와도 입력칸과 [다음] 버튼이 보이고 눌리는지 본다.
- [ ] **6. 지도 동작이 정상이다** — 휴대폰에서 지도 확대·이동, 핀 누르기, 바텀시트 끌어올리기를 해 보고 UT 바가 핀과 시트를 가리지 않는지 본다. (카카오 도메인 등록 필요)
- [ ] **7. 라이트·다크 모두 읽힌다** — 휴대폰의 화면 모드(라이트/다크)를 바꿔서 UT 바, 질문 창, 버튼 글자를 눈으로 읽어 본다.
- [ ] **8. 노치·주소창에 가려지지 않는다** — 휴대폰 세로·가로로 열어 UT 바가 위쪽 노치나 브라우저 주소창에 가려지지 않는지 본다.
- [ ] **9. 기존 서비스가 `?ut=1` 없이 똑같다** — 위 d번대로 운영 주소와 브랜치 주소를 `?ut=1` 없이 나란히 열어 같은 조작을 해 본다.
- [ ] **10. `?ut=1` 없이는 UT 파일을 부르지 않는다** — `?ut=1` 없는 주소에서 `F12` → 네트워크 탭 검색칸에 `ut/`를 쳐서 0건인지 본다.
- [ ] **11. 참가자 주소에 `dry`·`debug`·`fast`가 없다** — 보낼 주소를 눈으로 읽고, 그 주소(번호만 TEST로 바꿈)를 열었을 때 UT 바에 "기록" 버튼이 없는지 본다.
- [ ] **12. 참가자 번호가 겹치지 않고 TEST로 시작하지 않는다** — 번호 목록(P01, P02…)을 훑어보고 같은 번호가 두 번 없는지, TEST로 시작하는 번호가 없는지 본다.
- [ ] **13. 질문 문구와 제한 시간이 맞다** — `ut/questions.json`의 문구와 `limit_s`(과업 1은 90, 과업 2는 60)를 읽어 본다.
- [ ] **14. 연습 기록이 정리됐다** — 시트의 `is_test` 열이 TRUE인 줄을 필터로 골라 지우거나 따로 표시했는지 본다.
- [ ] **15. 시트·링크 공개 범위가 맞다** — 구글 시트 공유 설정에서 필요한 사람만 보이는지, 참가자 주소를 공개된 곳에 올리지 않았는지 본다.
