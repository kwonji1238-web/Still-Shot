# UT 모드 구글 시트 연결 안내

참가자가 답한 내용과 화면 이동 기록이 구글 시트에 한 줄씩 쌓이게 만드는 순서예요.
코드는 모르셔도 돼요. 아래를 위에서부터 그대로 따라 하세요.

> **먼저 알려 드려요.** 구글 화면(메뉴 이름과 위치)은 제가 직접 열어 확인하지 못했어요(확인 못함).
> 아래 이름은 제가 알고 있는 기준이고, 구글이 화면을 바꿨으면 조금 다를 수 있어요.
> 메뉴 이름이 안 보이면 비슷한 이름을 찾아보시고, 막히면 화면 캡처를 보여 주세요.
> **토큰(비밀번호 같은 글자)은 이 파일, 채팅, 문서에 붙여넣지 마세요.**

시간은 20분쯤 걸려요.

---

## 1. 구글 시트 만들기

1. 브라우저에서 구글 스프레드시트(sheets.google.com)를 열어요.
2. **빈 스프레드시트**를 새로 만들어요.
3. 왼쪽 위 이름을 `스틸스팟 UT 기록`처럼 알아볼 이름으로 바꿔요.
4. 탭 이름을 바꿀 필요는 없어요. 코드가 `responses`라는 탭을 알아서 만들고 첫 줄에 열 이름을 적어요.

## 2. 받아 적는 코드 붙여넣기

1. 시트 위쪽 메뉴에서 **확장 프로그램 → Apps Script**를 눌러요. 새 탭에 코드 편집 화면이 열려요.
2. 편집창에 이미 있는 글(`function myFunction() {...}`)을 **전부 지워요**.
3. 이 저장소의 `ut/apps-script/Code.gs` 파일을 열어 **전체를 복사**해서 편집창에 붙여넣어요.
4. 위쪽의 저장 버튼(디스크 모양)을 눌러요. 프로젝트 이름을 물으면 `스틸스팟 UT 받기`처럼 적어요.

## 3. 토큰 만들고 넣기

토큰은 "이 사이트에서 온 기록만 받는다"를 확인하는 비밀 글자예요. 시트와 사이트 양쪽에 **똑같은 글자**를 넣어야 해요.

1. 토큰을 만들어요. 비밀번호 생성기로 만든 24자 이상의 영문·숫자 조합이면 돼요. 한글·공백·특수문자는 피하세요. 메모장에 잠깐 적어 두세요(저장하지 말고 끝나면 지워요).
2. Apps Script 화면 왼쪽의 **프로젝트 설정**(톱니바퀴 모양)을 눌러요.
3. 아래로 내려가 **스크립트 속성**을 찾아 **스크립트 속성 추가**를 눌러요.
4. 속성 이름에 `UT_TOKEN`, 값에 1번에서 만든 토큰을 넣고 **스크립트 속성 저장**을 눌러요.

## 4. 웹 앱으로 배포하기 (주소 만들기)

1. Apps Script 화면 오른쪽 위 **배포 → 새 배포**를 눌러요.
2. 톱니바퀴(유형 선택)에서 **웹 앱**을 골라요.
3. 설정을 이렇게 해요.
   - **다음 사용자 인증 정보로 실행**: **나**
   - **액세스 권한이 있는 사용자**: **모든 사용자**
   - "모든 사용자"여야 참가자의 휴대폰이 로그인 없이 기록을 보낼 수 있어요.
4. **배포**를 눌러요.
5. 권한을 승인하라는 창이 나오면 내 구글 계정을 골라 허용해요. "확인되지 않은 앱" 경고가 나올 수 있어요. 내가 만든 코드라서 나오는 것이고, **고급 → (앱 이름)으로 이동**을 눌러 계속하면 돼요(확인 못함: 경고 문구는 구글이 바꿀 수 있어요).
6. 배포가 끝나면 **웹 앱 URL**이 보여요. `https://script.google.com/macros/s/.../exec`처럼 끝이 `/exec`인 주소예요. **복사**해서 메모장에 적어 두세요.

**배포가 됐는지 확인**: 복사한 주소를 새 브라우저 탭에 붙여 열어요. `ut-receiver ok`라는 글자만 보이면 정상이에요.

> 나중에 `Code.gs`를 고치면 저장만으로는 반영되지 않아요. **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 해야 해요(확인 못함: 버튼 이름).

## 5. 주소와 토큰을 사이트에 넣기

이 프로젝트는 값을 파일에 적지 않고 **환경변수**(비밀 값을 넣어 두는 칸)로 넣어요. 빌드(배포용 폴더를 만드는 일)가 `dist/ut/config.js`를 대신 만들어 줘요.
이름은 두 개예요: `UT_ENDPOINT`(4번의 웹 앱 URL), `UT_TOKEN`(3번의 토큰).

### 5-1. 내 컴퓨터에서 쓸 때 (`ut/PREVIEW.md` 참고)

1. 프로젝트 폴더의 `.env` 파일을 열어요. (`.env`는 깃에 올라가지 않는 파일이에요.)
2. 맨 아래에 두 줄을 추가해요. `=` 뒤에 값을 붙여 넣으세요. **따옴표나 공백 없이** 쓰세요.
   ```
   UT_ENDPOINT=여기에 웹 앱 URL
   UT_TOKEN=여기에 토큰
   ```
3. 저장해요.

### 5-2. Netlify에서 쓸 때 (배포본)

1. Netlify에 로그인해서 이 사이트를 열어요.
2. 사이트 설정(Site configuration)에서 **Environment variables**(환경변수)를 찾아요(확인 못함: 한국어 화면 이름).
3. **Add a variable**(변수 추가)로 `UT_ENDPOINT`, `UT_TOKEN`을 하나씩 추가해요.
4. 적용 범위(Scopes / deploy contexts)를 고르는 칸이 있으면 **브랜치 배포(Branch deploys)가 포함**되게 해 주세요(확인 못함: 기본값이 어떤지). `ut-mode` 브랜치 배포에서 값이 안 쓰이면 대부분 이 칸 때문이에요.
5. 변수를 추가한 **뒤에** 다시 배포해야 반영돼요. 이미 배포된 것은 예전 값 그대로예요.

### 5-3. 브랜치 배포에서 값이 쓰였는지 확인하는 방법

값은 화면에 출력하지 않고도 확인할 수 있어요.

1. **빌드 로그로 확인**: Netlify의 해당 배포를 열어 빌드 로그에서 이 줄을 찾아요.
   - `UT 설정 (UT_ENDPOINT 있음, UT_TOKEN 있음)` → 값이 들어갔어요.
   - `UT 설정 (UT_ENDPOINT 없음, UT_TOKEN 없음)` → 값이 안 들어갔어요. 5-2의 적용 범위를 다시 보세요.
2. **배포된 주소로 확인**: 브랜치 배포 주소 뒤에 `/ut/config.js`를 붙여 열어요.
   - `"endpoint":""` 처럼 **따옴표 안이 비어 있으면** 안 들어간 거예요.
   - 긴 주소와 글자가 들어 있으면 들어간 거예요. (이 주소는 누구나 열 수 있다는 점은 아래 "한계"를 보세요.)
3. **실제 전송으로 확인**: 배포 주소에서 `?ut=1&p=TEST01&debug=1`로 열어 한 번 진행하고, 시트에 줄이 들어오는지 봐요(`ut/PREVIEW.md`).

## 6. 시트에 쌓이는 열

| 열 | 뜻 |
| --- | --- |
| received_at | 시트가 받은 시각 |
| event_id | 기록 한 줄의 고유 번호(같은 번호는 두 번 적지 않아요) |
| session_id | 한 사람이 한 번 진행한 번호 |
| participant_id | 참가자 번호(P01 등). 이름·연락처·IP는 받지 않아요 |
| is_test | 연습용이면 TRUE (참가자 번호가 TEST로 시작하거나, 주소에 `dry=1`·`debug=1`이 있을 때) |
| mode | remote(원격) / inperson(직접 만남) |
| device | 화면 크기와 기기 종류(예: `390x844 mobile`) |
| client_ts | 참가자 휴대폰의 시각 |
| task | task1 / task2 / task3 |
| event | 일어난 일의 이름(ut_start, q_answer, task_end 등) |
| question_id | 질문 번호(Q1, S1 등) |
| value | 답 또는 결과 |
| task_elapsed_ms | 과업을 시작한 뒤 지난 시간(밀리초). 질문 창이 떠 있거나 화면이 가려진 시간은 뺐어요 |
| extra_json | 덧붙은 정보(글자 모양 그대로) |

연습 기록은 `is_test` 열에서 TRUE를 필터로 빼면 돼요.

## 7. 한계 (쉬운 말로)

- **주소와 토큰이 완전히 숨겨지지 않아요.** 이 서비스는 참가자의 휴대폰 브라우저가 직접 시트에 기록을 보내요. 그래서 주소와 토큰이 사이트 파일 안에 들어가고, 개발자 도구를 열 줄 아는 사람은 찾아낼 수 있어요.
- 그 사람이 마음먹으면 **엉뚱한 기록을 시트에 보낼 수는 있어요.** 다만 시트 안의 내용을 읽거나 지울 수는 없어요(받아 적기만 하는 코드라서요).
- 그래서 이렇게 막아 둬요: 토큰이 틀리면 안 받아요 / 한 번에 50줄·글자 수 제한 / 칸당 1,000자 제한 / 같은 번호는 한 번만 적어요.
- 더 막고 싶으면 이렇게 하세요: **테스트가 끝나면 4번의 웹 앱 배포를 중지하거나 삭제**하고, 다음 테스트에는 새 토큰을 써요. 토큰을 바꿀 때는 3번(스크립트 속성)과 5번(환경변수)을 **둘 다** 바꾸고 다시 배포해요.
- 주소를 모르는 사람이 찾아낼 가능성은 낮지만, **링크를 SNS 같은 공개된 곳에 올리지 마세요.**
- 참가자의 이름·연락처·IP는 받지 않아요. 다만 자유 서술(100자)에 참가자가 개인 정보를 적을 수 있으니, 시트 공유 범위는 필요한 사람에게만 주세요.

## 8. 안 될 때

브라우저는 "시트가 받았는지"를 알 수 없어요(구글의 보안 규칙 때문이에요). 그래서 화면에는 오류가 안 보여도 시트가 비어 있을 수 있어요. 아래 순서로 확인해요.

1. 4번의 주소를 브라우저로 열면 `ut-receiver ok`가 보이나요? 안 보이면 배포가 안 된 거예요.
2. 배포 설정이 **실행: 나 / 액세스: 모든 사용자**인가요? 아니면 4번을 다시 하세요.
3. 토큰이 3번과 5번에서 **글자 하나까지 같나요?** 앞뒤 공백이 없는지 보세요.
4. 환경변수를 넣은 뒤 **다시 배포**했나요?
5. Apps Script 화면 왼쪽의 **실행**(또는 실행 기록) 메뉴에서 오류가 났는지 봐요(확인 못함: 메뉴 이름). "토큰이 맞지 않는 요청"이 보이면 3번과 5번이 다른 거예요.
6. 시트로 못 보낸 기록은 참가자 휴대폰 브라우저에 남아 있다가, 같은 주소로 다시 접속하면 자동으로 다시 보내요. 급하면 진행자가 그 휴대폰에서 같은 주소 끝에 `&debug=1`을 붙여 열고(같은 참가자 번호여야 해요) **기록** 패널의 **[결과 복사]**로 복사해 시트에 붙여넣을 수 있어요. 시트로 못 보낸 기록도 이 글 아래에 함께 들어 있어요. 참가자 화면에는 이 버튼이 없어요.
7. 시트에 줄이 안 생기는데 브라우저 쪽이 의심되면 `?ut=1&debug=1`로 열어 **기록** 패널의 "전송 대기" 건수를 보세요. 계속 늘기만 하면 전송이 실패하는 거예요.

## 9. 다음 단계

시트가 준비됐으면 알려 주세요. 4단계에서 참가자 번호 `TEST`로 한 번 끝까지 돌려서 시트에 줄이 들어오는지 같이 확인해요.
