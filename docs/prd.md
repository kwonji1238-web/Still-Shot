## 1. 제품 개요 및 목표

작품 이름 하나로 촬영지의 정확한 위치와 갈 만한지 판단할 정보를 한곳에서 확인하고, 근처에서 뭘 할지까지 이어서 정하게 하는 모바일 우선 웹 서비스다. 촬영지가 주인공이고, 근처 코스는 보던 흐름에서 이어지는 선택 기능이다. 서비스가 목표로 하는 범위는 전국이며, 이번 구현의 데이터는 부산광역시 공공데이터뿐이다(데이터 제약).

### 해결 과제

**문제 정의:** 영화·드라마 속 장소가 궁금해서 가볍게 가 보려는 사람은, 정확한 위치와 갈 만한지 판단할 정보가 블로그·SNS·지도 앱에 흩어져 있어 찾는 데 오래 걸린다. 근처에서 뭘 할지도 따로 찾아야 해서, 결국 저장만 해 두고 가지 않는 경우가 많다.

근거는 설문 응답 10명 중 촬영지를 찾아본 6명 기준의 경향이다. 정보가 흩어져 있다 4명, 오래 걸렸지만 찾았다 5명, 가지 않은 이유는 거리 4명·정보 불확실 2명이었다. 표본이 작아서 결론이 아니라 방향 확인용으로만 쓴다.

| 목표 | 해결하는 문제 | 확인 방법 |
| --- | --- | --- |
| 찾기 | 흩어진 정보, 오래 걸림 | 검색부터 촬영지 위치 확인까지 걸린 시간 |
| 판단 | 갈 만한지 판단하기 어려움, 불확실한 정보 | 위치와 근처 정보를 보고 "가 볼 만하다"고 답하는 정도 |
| 이어가기 | 근처에 할 게 없음 | 코스를 스스로 발견해 근처에서 갈 곳을 고르는지 |

### 성공 지표 (KPI)

| 지표 | 정의 | 측정 방법 |
| --- | --- | --- |
| 과업 성공률 | 도움 없이 촬영지 위치를 정확히 말하고, 근처에서 갈 곳을 하나 고른 참가자의 비율 | 사용성 테스트 관찰 |
| 소요 시간 | 과업 시작부터 완료까지 걸린 시간 | 사용성 테스트 시간 기록 |
| 코스 발견율 | 안내 없이 스스로 근처 코스 버튼을 누른 참가자의 비율 | 사용성 테스트 관찰 |

테스트 과업은 "작품을 하나 골라서 촬영지가 어디인지 확인하고, 그 근처에서 들를 만한 곳을 하나 정해 보세요."이고, 참가자에게 "코스"라는 말은 쓰지 않는다. 참가자는 3~5명이며, 같은 과업으로 1차 배포본과 고친 수정본을 비교한다. 목표 수치는 아직 정하지 않았고, 1차 배포본 결과를 기준선으로 삼는다.

### 이번 5일의 범위와 일정

찾기는 반드시 해내고, 판단은 정확한 위치 안내와 근처 정보로 보여 주며, 이어가기는 선택 기능으로 둔다. 후기, 로그인, 저장, "내 주변 촬영지 찾기"는 만들지 않는다.

| 날짜 | 작업 | 산출물 |
| --- | --- | --- |
| 미정(6장) | 1차 배포: 기능 전체와 카카오 지도를 한 번에 배포한다. 배포 주소가 생기면 카카오 JavaScript SDK 도메인을 등록하고, 배포본에서 지도가 뜨는지 확인한다 | 배포 주소 |
| 미정(6장) | 1차 배포본 사용자 테스트 시작(3~5명) | 테스트 기록 |
| 11/1(일) | 1차 배포본 테스트·수정, 리뷰 그룹 상호 테스트 | 테스트 수치, 수정 기록 |
| 11/2(월) | 수정본 재테스트, README, 발표 자료 | 재테스트 수치, 문서 |
| 11/3(화) 10:00까지 | 최종 점검·제출 | 제출 |

1차 배포 날짜와 테스트 시작일은 6장에 열린 결정으로 두었다. 11/1 이후 날짜는 기존 계획 그대로이며, 배포가 늦어지면 함께 조정한다.

관련 문서: 화면별 세부 구성과 동작은 "와이어프레임 최종 명세", 색·서체·컴포넌트·말투는 design.md, 서비스 이름과 문구 원문은 "스틸스팟 네이밍·콘셉트 결정"을 따른다. 이 PRD와 다르면 해당 문서가 우선한다.

## 2. 타겟 유저 및 사용자 시나리오

대표 사용자는 영화·드라마 속 장소가 궁금해서 부담 없이 가 보려는 사람이며, 거주 지역과는 무관하다. 영화를 본 직후 찾아보는 사람(A)과 나들이·여행을 계획하는 사람(B)이 있고, 대표는 B다.

### 사용자 유형

| 유형 | 상황 | 이 제품에서 쓰는 범위 |
| --- | --- | --- |
| B (대표) | 나들이·여행을 계획하며 "여기서 찍었다는데 한번 바람 쐬러 가볼까? 근처에 다른 거 뭐 할 거 있나?" 하는 가벼운 마음 | 촬영지 확인 → 근처 정보 → 코스 |
| A | 영화·드라마를 본 직후 바로 찾아본다 | 촬영지 확인까지만 써도 된다 |

설문(10명)에서 쓸 것 같은 때는 여행 계획 4명, 영화 본 직후 3명, 주변을 지나다가 3명이었다. 본 직후를 고른 3명은 모두 촬영지를 찾아본 경험이 있고 모두 방문했다. 방문 없이 저장만 한 3명은 본 직후 장면이 아니었다. 한계도 있다. 응답자가 30대 6명, 20대 2명, 10대 2명이라 지인 중심일 수 있고, "가볍게 바람 쐬러"는 설문 문항이 아니라 설계자의 해석이다.

### 페인 포인트와 대응

수치는 촬영지를 찾아본 6명 기준이다.

| 페인 포인트 | 근거 | 이 제품의 대응 |
| --- | --- | --- |
| 정보가 블로그·SNS·지도 앱에 흩어져 있다 | 4명 | 작품 이름 하나로 촬영지 위치와 근처 정보를 한곳에 모은다 |
| 찾는 데 오래 걸린다 | 5명이 "오래 걸렸지만 찾았다" | 검색 한 번으로 촬영지 목록과 위치를 보여 준다 |
| 갈 만한지 판단하기 어렵고 정보가 불확실하다 | 가지 않은 이유로 2명 | 지도 핀과 주소, 근처 관광지·식당 미리보기, 출처 문구를 함께 보여 준다 |
| 촬영지에 가도 할 게 없다 | 자유 응답: "촬영지에 가면 딱히 할 건 없더라", "주변 관광장소도 안내해주면 좋겠다" | 근처 미리보기와 선택형 코스를 보여 준다 |
| 거리가 멀어서 가지 않는다 | 가지 않은 이유로 4명 | 제품이 해결할 수 없다. 근처에 할 것을 보여 줘서 갈 이유를 늘리는 데까지만 다룬다 |

자유 응답에는 "정확한 위치, 관련 후기"도 있었다. 후기는 이번 범위에서 만들지 않는다.

### 핵심 사용 플로우 (시나리오)

아래는 설계 가정에 따른 시나리오이며 실제 사용 데이터가 아니다.

1. **B (대표):** 주말에 바람 쐴 곳을 찾던 사용자가 최근 본 작품 이름을 검색한다. 촬영지 목록을 훑다가 한 곳을 골라 위치와 근처 정보를 본다. "근처 코스 보기"로 촬영지 → 관광지 → 식당 순서를 확인하고 갈 곳을 하나 정한다.
2. **A:** 영화를 보고 나온 사용자가 작품 이름을 검색해 촬영지가 어디인지만 확인하고 나간다. 코스는 열어 보지 않아도 된다.
3. **좌표 없는 촬영지:** 목록에서 고른 곳에 지도 위치가 없으면 주소만 확인하고, 주소를 복사해서 다른 지도 앱에서 찾는다.

## 3. 기능 요구사항

우선순위(P0·P1)와 버전(v0·v1)을 나누지 않고, 아래 기능을 모두 1차 배포(v0)에 한 번에 담는다. 데이터나 이용 조건이 아직 정해지지 않은 항목은 "선행 조건" 열에 적고, 값이 있을 때만 해당 칸을 보여 주는 방식으로 넣는다. 1장 일정표에서도 v0·v1 구분을 없앴고, 새 날짜는 6장에서 정한다. 카카오 지도, 지도 위 시트, PC 지도 구성, S4의 전체 경로 지도, S2의 근처 장소 핀도 1차 배포 범위에 넣는다. 화면별 세부 구성과 동작은 "와이어프레임 최종 명세"를, 시각 값은 design.md를 따르며 아래 표는 그 요약이다. "(제안)"은 와이어프레임에 제안으로 표시되어 있고 아직 확정되지 않은 항목이다.

### 1차 배포(v0) 기능 목록

| ID | 기능 | 요구사항 | 화면 | 선행 조건 |
| --- | --- | --- | --- | --- |
| F-01 | 작품 검색 | 홈 검색창에 입력하면 같은 화면 아래에 일치하는 작품이 바로 뜬다(E1). 항목은 작품명 + "촬영지 N곳"이고, 일치한 글자는 굵게, 앞부분 일치를 위로 정렬한다. 띄어쓰기를 무시한 부분 일치(제안). 항목을 누르면 S2로 가고, 별도 결과 화면은 없다. 빈 입력이면 안내하고, "취소"는 입력을 지우고 홈으로 돌아간다. | S1, E1 | 없음 |
| F-02 | 촬영지 목록 | S2 시트 안의 목록. 작품명, "촬영지 N곳"과 촬영지 줄(번호, 촬영지명, 주소)을 보여 준다. 번호는 지도 핀 번호와 같다. 좌표 없는 촬영지는 번호 대신 "–"와 "주소만 표시" 칩을 달고 맨 뒤에 둔다. 줄을 누르면 S3로 간다. | S2 | 목록 정렬 기준(6장) |
| F-03 | 촬영지 상세 | 위에서 아래로 사진(있을 때, 220px), 작품 칩, 촬영지명, 주소, "지도로 보기"(채움 버튼, F-12), "근처에 이런 곳", "이 근처 코스 보기", "같은 작품의 다른 촬영지", 출처 문구 순서로 둔다. 사진이 없으면 사진 칸을 없애고 낮은 헤더로 시작한다. 사진 출처 표기는 달지 않는다. 사진 높이는 근처 미리보기와 코스 버튼이 첫 화면(844px 기준)에 들어오도록 220px로 잡았다. | S3, S3 사진 없음 | 없음(사진은 F-16) |
| F-04 | 근처 미리보기 | 촬영지 좌표에서 가까운 관광지 최대 2곳 + 식당 최대 1곳. 줄마다 이름과 "분류 · 직선 N"을 적는다(1km 미만은 10m 단위 m, 이상은 소수 첫째 자리 km). 관광지·식당 모두 사진 주소가 있으면 사진 썸네일, 없으면 빈 프레임 타일(아이콘 모양 미정). 후보가 없는 칸은 만들지 않는다. 줄을 누르면 S5로 간다(오른쪽 `›`, 눌림 배경). 코스는 따로 코스 버튼으로 간다. | S3 | 근처 반경 확정(6장) |
| F-05 | 규칙 기반 근처 코스 | "이 근처 코스 보기"를 누르면 S4로 간다. 구성은 촬영지(출발) + 관광지 최대 2 + 식당 최대 1 + 카페 최대 1(근처에 있을 때만)이고, 후보가 모자라면 그 카드를 만들지 않는다. 번호와 연결선이 있는 세로 타임라인에 카드를 놓고, 카드에는 분류 칩, 이름, "직선 N"(촬영지 카드는 작품명)을 둔다. 카드 전체를 누를 수 있어 촬영지 카드는 S3로, 관광지·식당·카페 카드는 S5로 간다. 끝에 "[작품명]의 다른 촬영지 보기" 버튼(→ S2). ## 4. 유저 플로우 및 화면 정의

홈에서 작품을 고르면 지도와 촬영지 목록이 열리고, 촬영지 상세에서 위치와 근처 정보까지 확인하면 과업을 마칠 수 있다. 코스(S4)는 상세에서 한 단계 더 들어가는 선택이고, 코스의 장소를 누르면 장소 상세(S5)로 간다. 화면은 모바일 390px 기준 5장(S1~S5)이며, 예외·상태 화면 3장(E1~E3), 시트 높이 3단계(접힘·반 열림·펼침), 사진 없음 상태, 768px 이상의 PC 화면 2장이 따로 있다. 세부 구성과 동작은 "와이어프레임 최종 명세", 색·서체·컴포넌트는 design.md가 기준이다.

**화면 이동 플로우 · 필수 경로 4단계, 예외 2곳**

```
S1 홈 → E1 검색 중 → S2 촬영지(지도 + 시트) → S3 상세 ⇢ S4 근처 코스 (선택) ⇢ S5 장소 상세 (선택)
S3 ⇢ S5 (근처 미리보기 줄)
S5 ⇢ S3 ("[촬영지명] 보러 가기")
E1 ⇢ E2 결과 없음 → S1 (다시 입력)
S2 ⇢ E3 좌표 없음 (주소만 표시)
S1 ⇢ S2 ("요즘 뜨는 촬영지"를 누르면 검색을 건너뜀)

→ 필수 이동   ⇢ 선택·예외 이동   S3 = 과업을 끝낼 수 있는 화면
```

실선은 필수 이동이고 점선은 선택·예외 이동이다. S3에서 근처 정보까지 보면 과업이 끝나므로, S4 진입 여부가 곧 코스 발견율이 된다. S5는 코스의 장소를 눌렀을 때만 들어가는 선택 화면이다.

| S2 촬영지 지도 + 시트 | 어디서 찍었는지 파악한다 | 전체 화면 지도, 왼쪽 위 뒤로 가기(지도 위에 작품명은 두지 않는다, 2026-10-30 사용자 결정), 번호 핀(촬영지를 고르면 근처 장소 핀이 따로 뜬다), 아래 시트(머리말: 포스터 자리 · 작품명 · 개봉연도 · 장르 · "촬영지 N곳" · 펼침/접기 버튼 / 목록: 번호 + 촬영지명 + 주소) | 시트는 접힘 · 반 열림(기본) · 펼침 3단계이고 손잡이와 머리말 버튼으로 바꾼다. 작품을 고르면 시트를 뺀 지도 영역 안에 모든 핀이 들어오게 맞춘다. 핀을 누르면 해당 줄이 강조되고, 그 촬영지의 근처 장소 핀(관광지 최대 2 + 식당 최대 1, 번호 없음)이 지도에 따로 뜬다. 다른 촬영지를 고르면 근처 핀이 그 촬영지 것으로 바뀌고, 근처 핀은 눌러도 이동하지 않는다(제안). 줄을 누르면 S3로 간다. 펼침에서는 머리말 아래만 스크롤한다(줄거리 → 목록 → 출처 문구). 좌표 없는 촬영지는 번호 없이 "주소만 표시"로 맨 뒤에 둔다 |
| S3 촬영지 상세 | 갈 만한지 판단한다 | 상단 사진(220px, 있을 때만), 작품 칩, 촬영지명, 주소, "지도로 보기"(채움 버튼), "근처에 이런 곳"(관광지 2 + 식당 1), "이 근처 코스 보기"(고스트 버튼), "같은 작품의 다른 촬영지" 칩 3개(제안), 출처 문구 | "지도로 보기"는 S2로 이동해 이 촬영지의 핀을 강조하고 지도 중앙에 두며, 시트는 반 열림이고 근처 장소 핀이 함께 뜬다. 지금 데이터에는 촬영지 사진이 없어 사진 칸이 없는 상태(낮은 헤더)가 기본이다. 근처 미리보기 줄을 누르면 S5로 간다 |
| S4 근처 코스 (선택) | 오늘 들를 곳을 정한다 | 뒤로 가기 + "근처 코스", "[촬영지명] 근처 코스" 제목과 부제, 전체 경로 지도(번호 핀 + 직선, 제안), 세로 타임라인(번호 + 카드: 촬영지 → 관광지 최대 2 → 식당 최대 1 → 카페 최대 1, 카드마다 분류 칩 · 이름 · "직선 N"), "[작품명]의 다른 촬영지 보기"(고스트 버튼), 출처 문구 | 카드 전체를 누를 수 있다. 촬영지 카드는 S3로, 나머지 카드는 S5로 간다. 장소별 지도 링크는 두지 않고, 코스 전체는 위쪽 경로 지도에서 본다. 지도의 번호는 카드 번호와 같고, 핀을 눌러도 이동하지 않으며(제안), 코스 순서가 정해진 뒤에 그린다. 버튼은 S2로 간다. 코스 설명을 기다리는 동안 "다음 장면을 고르고 있어요", 완성되는 순간 "찾았다! 이 근처 코스예요"를 보인다(design.md 4-12). 후보가 적으면 있는 곳만 보여 주고 빈 카드를 만들지 않는다. 뒤로 가면 같은 촬영지의 S3 |
| S5 장소 상세 | 코스에 나온 장소의 소개와 주소를 본다 | 상단 사진(220px, 사진 주소가 있을 때만), 분류 칩 + "[촬영지명]에서 직선 N", 장소 이름, 주소, "주소 복사"(고스트 버튼), "소개"(소개글이 있을 때만, 4줄까지), "[촬영지명] 보러 가기"(고스트 버튼), 출처 문구 | 뒤로 가면 들어온 화면(S3 또는 S4). "보러 가기"는 그 촬영지의 S3로 간다(막다른 길 방지). 지도 버튼은 없다. 식당·카페는 소개글이 없어 "소개" 칸이 빠진다. 출처 문구는 관광지·식당 데이터 제공처를 확인한 뒤 정한다(6장) |
| E2 검색 결과 없음 | 다시 입력하거나 다른 작품을 고른다 | 입력창 + "취소", 안내 문구 "아직 이 작품의 촬영지를 못 찾았어요. 다른 작품 이름으로 검색해 보세요", "요즘 뜨는 촬영지" 목록 3줄 | 원인을 하나로 단정하지 않고 지역 이름도 쓰지 않는다(서비스 방향은 전국). 홈과 같은 목록으로 막다른 길을 막는다 |
| E3 좌표 없는 촬영지 | 주소만 확인한다 | 사진(있을 때), 작품 칩, 촬영지명, 주소, 안내 상자 "지도에는 표시할 수 없어요. 주소만 안내해요", "주소 복사"(고스트 버튼), "같은 작품의 다른 촬영지" 칩 3개(제안), 출처 문구 | "지도로 보기", "근처에 이런 곳", 코스 버튼은 비활성이 아니라 숨긴다(좌표가 없어 거리를 구할 수 없음). 전체의 약 5%(111건 / 2,193건). 안내 상자에는 아이콘과 색이 없다. "주소 복사"를 누르면 토스트로 알린다(예시 "주소를 복사했어요", 확정 아님) |
| PC 지도 + 목록 | 지도를 보며 촬영지를 고른다 | 상단바(서비스 이름 + 현재 작품명이 들어간 검색창), 왼쪽 목록 패널(폭 360px, 1023px 이하 300px: 머리말 + 촬영지 목록 + 출처 문구), 나머지는 지도(촬영지를 고르면 근처 장소 핀이 뜬다) | 패널은 항상 열려 있어 시트 단계가 없다. 목록 번호 = 핀 번호. 홈·검색(S1·E1·E2)은 PC에서도 가운데 한 칸, 최대 폭 480px |
| PC 촬영지 상세 | 목록을 보며 상세를 비교한다 | 지도 위 상세 패널(폭 400px, 지도 왼쪽 위 여백 16px): 사진 168px(있을 때, ✕) → 작품 칩 → 촬영지명 → 주소 → "근처에 이런 곳" 3줄 → "이 근처 코스 보기" → 출처 문구 | 목록 줄이나 핀을 누르면 둘 다 강조되고 패널이 뜨며 근처 장소 핀도 지도에 뜬다. ✕는 패널만 닫는다. "지도로 보기"와 "같은 작품의 다른 촬영지"는 없다. 코스를 열면 패널 내용이 S4로, 코스의 장소를 누르면 촬영지는 S3, 나머지는 S5 내용으로 바뀐다(제안). 코스를 열면 패널에는 경로 지도를 두지 않고, 메인 지도에 코스 번호 핀과 선을 겹쳐 그린다(제안). 목록은 그대로 둔다 |

### 되돌아가기와 이동 규칙

- 뒤로 가기는 바로 전 화면으로 돌아가고, 지도 위치와 시트 높이를 그대로 복원한다.
- "지도로 보기"는 뒤로 가기와 다르다. S2로 이동해 이 촬영지의 핀을 강조하고 지도 중앙에 두며, 시트는 반 열림에 해당 줄이 강조되며 근처 장소 핀이 뜬다.
- S4에서 뒤로 가면 같은 촬영지의 S3로 돌아온다. S5에서 뒤로 가면 들어온 화면(S3의 근처 미리보기 또는 S4)으로 돌아온다.
- 홈의 "요즘 뜨는 촬영지"로 들어간 S2에서 뒤로 가면 홈으로 돌아간다.
- S3의 "같은 작품의 다른 촬영지" 칩은 목록을 거치지 않고 옆으로 이동한다(제안).
- 접힘 상태에서 핀을 눌렀을 때 시트를 반 열림까지 자동으로 올릴지는 미정이다(제안은 자동으로 올림).

### 화면 구성 결정

- **검색 결과를 별도 화면으로 두지 않는다.** 홈에서 입력과 동시에 고르며, 이동이 한 단계 적다. 대안은 결과 화면 분리이며, 비슷한 이름의 작품이 많을 때 유리하지만 이동이 한 단계 늘어난다.
- **코스는 상세에서 한 단계 더 들어가는 선택으로 둔다.** S3 미리보기로 맛보기를 주고 더 보고 싶은 사람만 S4로 간다. 대안은 상세 안의 바텀시트이며, 화면 이동은 없지만 구현이 늘어난다.
- **코스 카드는 눌러서 장소 상세(S5)로 가고, 장소별 지도 링크는 두지 않는다.** 와이어프레임 변경 요청 8에서 확정했다. 대신 코스 전체를 한눈에 보는 경로 지도를 S4 위쪽에 두고(새 화면은 만들지 않는다), 근처 장소 핀은 S2 지도에서 촬영지를 고를 때 따로 보여 준다. 경로 지도와 근처 장소 핀을 한 지도에 섞지 않는다. 사용자 결정이다.
- **같은 작품의 다른 촬영지로 옆 이동한다(제안).** 여러 곳을 비교하는 사람이 상세와 목록을 왕복하지 않아도 된다.
- **작품 정보는 시트 머리말에 고정한다.** 지도를 넓게 봐도 어떤 작품인지 잃지 않으며, 작품 상세 화면을 따로 두지 않아 이동이 한 단계 적다. 대안은 작품 상세 분리이며 이번 범위를 넘는다.
- **구·군 필터 칩은 두지 않는다.** 삭제로 확정했다.

## 5. 예외 케이스 및 제약 사항

검색·거리 계산·규칙 기반 코스는 브라우저에서 데이터 파일로 처리하므로, 데이터를 불러온 뒤에는 네트워크 지연의 영향이 없다. 지연·실패의 영향을 받는 것은 데이터 파일 로드, 지도 SDK(F-11), OpenAI 코스 설명(F-13)이고, 어느 쪽이 실패해도 목록·상세·규칙 기반 코스(F-05)는 그대로 쓸 수 있어야 한다. "(제안)"은 아직 확정되지 않은 처리다.

## 6. 열린 결정과 확인 필요 항목

아직 정해지지 않았거나 직접 확인하지 못한 항목입니다. 상태는 세 가지로 구분합니다. 제안 있음은 대안이 있고 확정만 남은 것, 미정은 대안도 아직 정하지 않은 것, 확인 필요는 사실 여부를 직접 확인하지 못한 것입니다. 시점은 현재 일정 기준의 제안입니다.
